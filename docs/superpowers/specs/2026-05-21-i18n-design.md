# 国际化（i18n）功能设计

**日期：** 2026-05-21
**状态：** 已确认
**范围：** 前端 UI + Ant Design + API 错误消息全栈国际化，首批 zh_CN / en_US

---

## 方案选型

选择 **i18next 全栈方案**（方案 A）。

| 包 | 位置 | 用途 |
|---|---|---|
| `i18next` | `@erp/admin` + `@erp/core` | 核心翻译库，前后端共用 |
| `react-i18next` | `@erp/admin` | React 绑定（`useTranslation`, `<Trans>`） |
| `i18next-browser-languagedetector` | `@erp/admin` | 浏览器语言自动检测 |

**替代方案对比：**
- 方案 B（自定义轻量）：零依赖但缺复数规则、插值缓存、命名空间隔离，扩展成本高
- 方案 C（FormatJS）：ICU 语法学习曲线陡，后端不兼容导致前后端不一致，bundle 体积最大

## 文件组织

```
packages/admin/src/
├── locales/
│   ├── zh_CN/
│   │   ├── common.json        # 通用 UI（按钮、提示、导航、品牌）
│   │   ├── auth.json          # 登录/注册/忘记密码页
│   │   └── dashboard.json     # 仪表盘/首页
│   └── en_US/
│       ├── common.json
│       ├── auth.json
│       └── dashboard.json
├── i18n.ts                     # i18next 初始化 + Ant Design locale 映射
└── ...

packages/core/src/
└── i18n/
    ├── index.ts                # i18next Node 端初始化 + 语言提取工具
    └── __tests__/
        └── i18n.test.ts
```

### 命名空间

- **`common`** — 跨页面共享文案（品牌名、导航标签、通用按钮等）
- **`auth`** — 登录/注册/忘记密码页面
- **`dashboard`** — 首页仪表盘（统计卡片、动态信息流、快捷操作）

### Key 命名规范

嵌套点号分隔：`<命名空间>.<区域>.<语义key>`，如 `auth.login.title`、`dashboard.stats.activeUsers`。

### Fallback 链

```
zh_CN → zh → en_US → key 本身
```

开发阶段 key 本身可见，方便发现未翻译项。

## 前端 i18n 初始化

### `i18n.ts` 核心逻辑

```ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: { zh_CN: {...}, en_US: {...} },
    fallbackLng: 'en_US',
    defaultNS: 'common',
    ns: ['common', 'auth', 'dashboard'],
    detection: {
      order: ['localStorage', 'navigator'],
      lookupLocalStorage: 'erp_lang',
      caches: ['localStorage'],
    },
    interpolation: { escapeValue: false },
  });

export default i18n;
```

### `main.tsx` 集成 Ant Design locale

`i18n.ts` 中维护 locale 映射：

```ts
import zhCN from 'antd/locale/zh_CN';
import enUS from 'antd/locale/en_US';

const antdLocales = { zh_CN: zhCN, en_US: enUS };

export function getAntdLocale() {
  return antdLocales[i18n.language] || enUS;
}
```

`main.tsx` 中：

```tsx
const [locale, setLocale] = useState(getAntdLocale());
i18n.on('languageChanged', () => setLocale(getAntdLocale()));

<ConfigProvider locale={locale} theme={...}>
  <App />
</ConfigProvider>
```

### 页面中使用

```tsx
import { useTranslation } from 'react-i18next';

function LoginPage() {
  const { t } = useTranslation('auth');
  return <Card title={t('login.title')} subtitle={t('login.subtitle')} />;
}
```

### `index.html` 动态 lang 属性

启动时 JS 设置 `document.documentElement.lang = i18n.language`。

## 语言检测与切换

### 登录页自动检测

检测优先级：`localStorage('erp_lang')` → `navigator.language`

登录页不显示语言切换按钮，保持简洁。首次访问自动适配浏览器语言，后续可在顶部导航栏手动调整。

### 顶部导航栏语言切换

`AppHeader.tsx` 用户头像左侧新增语言切换下拉：

- Ant Design `<Dropdown>` + `<Button type="text" icon={<GlobalOutlined />}>`
- 两个选项：`中文` / `English`，对应 `zh_CN` 和 `en_US`
- 切换调用：`i18n.changeLanguage(lang)` + `localStorage.setItem('erp_lang', lang)`
- 未来扩展更多语言时，替换为 `<Select>` 或带搜索的 dropdown

### 状态同步原则

- `i18n.language` 是单一真实来源（i18next 内部维护）
- Zustand store 不重复存储语言状态
- 若需要 store 感知（如 API 请求携带 `Accept-Language`），通过 `i18n.on('languageChanged')` 事件同步

## 后端 i18n

### API 错误消息国际化

`@erp/core/src/i18n/index.ts`：

```ts
import i18n from 'i18next';

i18n.init({
  resources: {
    zh_CN: {
      errors: {
        auth: { invalid_credentials: '用户名或密码错误', ... },
        validation: { required: '{{field}} 为必填项', ... },
      },
    },
    en_US: {
      errors: {
        auth: { invalid_credentials: 'Invalid username or password', ... },
        validation: { required: '{{field}} is required', ... },
      },
    },
  },
  fallbackLng: 'en_US',
  defaultNS: 'errors',
});
```

### 语言提取

- Controller 从请求 `Accept-Language` header 读取
- 或在 Vite JWT 中间件中从用户记录读取偏好
- 提供工具函数：`getRequestLocale(req) → 'zh_CN' | 'en_US'`

```ts
import i18n from 'i18next';

function login(ctx) {
  const t = i18n.getFixedT(getRequestLocale(ctx.req));
  throw new AppError(t('errors:auth.invalid_credentials'));
}
```

## 业务模块翻译（数据库，预留）

`erp_translations` 表结构（首批创建但不填充使用）：

```sql
CREATE TABLE erp_translations (
  id SERIAL PRIMARY KEY,
  module VARCHAR(64),
  resource_type VARCHAR(32),  -- 'model', 'field', 'view', 'menu'
  resource_id VARCHAR(128),   -- 'res.partner' / 'res.partner,name'
  lang VARCHAR(10),
  value TEXT NOT NULL,
  UNIQUE(module, resource_type, resource_id, lang)
);
```

首批范围：前端 JSON 文件 + API 错误消息 + 数据库表结构预留。业务模块翻译延后实现。

## 设计决策汇总

| 决策 | 选择 | 理由 |
|------|------|------|
| i18n 库 | i18next | 前后端统一，生态最成熟 |
| 前端翻译存储 | 静态 JSON 文件 | 构建时打包，零延迟 |
| 业务翻译存储 | 数据库（预留） | 支持运行时更新，首批不填充 |
| UI 翻译方案 | 混合：JSON + DB 预留 | 紧耦合 UI 文本走静态文件，业务数据走数据库 |
| 语言检测 | localStorage → navigator | 用户选择优先 |
| 检测位置 | 登录页自动 + 顶部导航手动 | 首次适配 + 随时可改 |
| 语言状态 | i18n.language 单一来源 | 避免双源不一致 |
| 覆盖范围 | 前端 UI + Ant Design + API 错误 | 全栈覆盖 |
| 首批语言 | zh_CN + en_US | 满足当前需求，架构支持后续扩展 |
| 后端语言提取 | Accept-Language header | HTTP 标准做法 |
